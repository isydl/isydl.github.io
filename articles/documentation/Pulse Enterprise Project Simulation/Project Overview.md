### 项目概述（Project Overview）

**项目名称**：内部 Helpdesk 工单管理系统（Internal Helpdesk Ticket Management System）  
**文档版本**：V1.0  
**目标读者**：开发团队（及后续维护者）

---

#### 1. 项目背景与痛点（Background & Pain Points）

目前团队/公司的内部支持流程依赖邮件和即时通讯，存在以下问题：

- **信息碎片化**：请求散落在不同人的邮箱里，难以追踪。
- **责任不清**：问题无人认领时，容易变成“三不管”地带。
- **状态不透明**：提需求的人不知道进度，处理的人总被催促。
- **缺乏沉淀**：解决问题的过程没有存档，同类问题重复解答。

#### 2. 项目目标（Project Goals）

构建一个**轻量级、集中化**的工单流转平台，实现以下核心目标：

- **统一入口**：所有内部服务请求（IT故障、业务咨询、权限申请）全部走系统提单。
- **责任到人**：引入“接单”机制，明确当前处理人。
- **状态可视**：用户能实时看到工单处于哪个环节（待处理/处理中/待确认/已关闭）。
- **留痕沉淀**：记录每一次沟通和状态变更，形成知识库雏形。

#### 3. 项目范围（Scope）— **（最重要的一栏，用来防烂尾）**

**✅ 包含（In-Scope）—— MVP 首发版本：**

- 用户登录与简单的角色区分（普通用户、客服、管理员）。
- 工单的发布（CRUD：新建、列表筛选、详情查看、逻辑删除）。
- **核心状态机流转**（严格限定：未处理→处理中→待确认→已完成，以及异常退回）。
- 工单详情页内的**评论回复（时间线）**。
- 基本的附件上传（单文件≤5MB，限 jpg/png/pdf）。

**❌ 不包含（Out-of-Scope）—— 明确划掉，绝不在第一版做：**

- 复杂的可视化报表/大屏统计（只做简单的列表计数）。
- 真正的邮件发送（第一版用 `System.out.println` 模拟日志，或者只做异步占位）。
- 单点登录（SSO）或 LDAP 对接（采用最简单的本地账号密码登录）。
- 移动端 APP（仅适配 PC 端浏览器）。
- 工单之间的关联/依赖（父子工单）。

#### 4. 技术定位与选型（Tech Stack & Positioning）

**技术定位**：标准的 **单体应用（Monolith）**，分层架构（Controller-Service-Mapper）。不采用微服务，以降低部署和维护复杂度。

**具体技术栈清单：**

| 层级             | 技术选型                                    | 选型理由（用于技术评审答辩）                                 |
| :--------------- | :------------------------------------------ | :----------------------------------------------------------- |
| **后端框架**     | Spring Boot 3.x                             | 主流 Java 生态，生态完善，上手快。                           |
| **ORM 框架**     | MyBatis-Plus                                | 简化单表 CRUD，内置乐观锁插件，适合快速开发。                |
| **安全框架**     | Sa-Token 或 Spring Security                 | 轻量级鉴权，支持角色拦截和注解式权限控制。                   |
| **数据库**       | MySQL 8.x                                   | 关系型数据库，满足事务一致性要求（状态流转必须有事务）。     |
| **缓存（可选）** | Redis（仅做分布式 Session 或 Token 黑名单） | 非必须，第一版可用内存缓存替代；若部署简单可先不用。         |
| **前端框架**     | Vue 3 + Element Plus 或 Thymeleaf           | 后者适合全栈一把梭，前者适合前后端分离（根据你的熟练度选）。 |
| **文件存储**     | 本地磁盘存储（绝对路径映射）                | 第一版不接云 OSS，直接存本地指定文件夹，简化部署。           |
| **构建工具**     | Maven                                       | 依赖管理标准。                                               |

#### 5. 核心模块逻辑划分（High-Level Module Division）

基于业务，后端代码将划分为以下 6 个核心包（Package）：

1. **`auth` 包**：登录、注册、Token 生成、全局权限拦截。
2. **`ticket` 包**：工单的增删改查、列表分页、动态条件过滤。
3. **`state` 包**：**（核心心脏）** 状态机引擎，包含所有状态流转的校验逻辑和枚举定义。
4. **`comment` 包**：评论/回复的增删改，关联工单 ID。
5. **`attachment` 包**：文件的上传、下载、大小/类型校验。
6. **`notification` 包**：通知模块（第一版只写接口，不做真实实现，仅打印日志）。

#### 6. 非功能性需求（NFRs - Non-Functional Requirements）

- **健壮性**：任何状态流转错误必须抛出明确的业务异常（`BusinessException`），不能直接报 500 空指针。
- **可维护性**：状态流转逻辑必须**集中管理**，严禁在 Controller 层写大量的 `if-else` 判断状态。
- **日志规范**：关键操作（登录、状态变更、删除）必须打印操作人、操作时间、操作前后内容（`@Slf4j`）。
- **API 规范**：统一返回格式 `Result<T>`（包含 code, msg, data）。

#### 7. 开发环境与启动方式（Onboarding）

- **JDK 版本**：17 或 21（LTS 版本）。
- **数据库初始化**：项目启动时自动执行 `schema.sql` 建表，插入默认管理员账号（`admin/123456`）。
- **本地启动命令**：`mvn clean spring-boot:run`
- **接口测试**：集成 Knife4j（Swagger 增强），启动后访问 `/doc.html` 即可调试所有 API。
